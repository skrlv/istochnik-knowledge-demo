# ИСТОЧНИК

Демонстрационный помощник по загруженным инструкциям: находит дословный фрагмент, открывает его источник и помогает подготовить вопрос человеку, если сведений недостаточно.

## Статус

Реализованы браузерный интерфейс и отдельный локальный сервер. Публикация и итоговая проверка интерфейса ожидают подтверждения владельцем задачи. Планируемый отдельный репозиторий: `skrlv/istochnik-knowledge-demo`; планируемый адрес: `https://skrlv.github.io/istochnik-knowledge-demo/`. Этот адрес пока не является заявлением о состоявшейся публикации.

Проект не использует платный API или языковую модель. Ключи, аккаунт внешнего ИИ и установка пакетов не нужны. Учебные документы компании «Линия», регламенты, сроки и названия полностью вымышлены.

## Что можно сделать

- Добавить инструкции `.txt` и `.md` в UTF-8, открыть документ, заменить его новой редакцией или удалить.
- Задать вопрос и получить точную выдержку с названием документа, разделом и строками; открыть полный исходник с подсветкой фрагмента.
- Увидеть честное отсутствие сведений или необходимость уточнения при различающихся подходящих источниках.
- До сохранения изменить вопрос, контекст и необязательный контакт обращения; посмотреть приложенные цитаты и отключить их включение.
- Сохранить обращение в локальную очередь, просмотреть контекст, поменять статус, скачать отдельное обращение или очередь в JSON. Можно скачать черновик до его сохранения.
- По собственному выбору включить сохранение браузерных данных. В браузерном режиме доступны удаление отдельных обращений и очистка очереди.

Сохранение и экспорт не отправляют сообщение реальному сотруднику. Почта, Telegram и CRM не подключены; экспорты нужно передавать человеку самостоятельно. Импорт экспортированной очереди в интерфейсе не реализован.

## Запуск и проверка

Нужны Node.js 22+ и входящий в него npm. Внешних зависимостей нет; `npm install` не требуется. Выполните команды в корне распакованного проекта:

```sh
npm start
```

Откройте локальный адрес `http://127.0.0.1:4316/`. Это серверный режим: интерфейс использует локальный процесс для поиска, а очередь сохраняется в файл на этом компьютере. Остановка — `Ctrl+C` в окне запуска. Настройки порта, папки данных, API и удаление серверной очереди описаны в [LOCAL-SERVER.md](docs/LOCAL-SERVER.md).

Остальные команды:

```sh
npm test
npm run build
npm run check
```

`npm test` запускает тесты движка и локального HTTP-сервера. `npm run build` пересоздаёт `dist/`, копируя только статические файлы. `npm run check` проверяет синтаксис клиентского кода, движка и сервера, затем запускает тесты и сборку. Команды не отправляют обращения и не используют платные сервисы.

Для просмотра именно статического браузерного режима после сборки можно использовать Python 3, если он установлен:

```sh
python3 -m http.server 4318 --bind 127.0.0.1 --directory dist
```

Откройте `http://127.0.0.1:4318/`. Это отдельный локальный просмотр статических файлов; серверной очереди в нём нет. Открытие `index.html` через `file://` не поддерживается: для загрузки модулей и учебной базы нужен HTTP.

## Сценарий за три минуты

1. При первом открытии загружаются четыре учебных документа «Линии». Нажмите «Доступ в CRM» или задайте «Как получить доступ в CRM?». Ожидается дословный фрагмент о заявке, согласовании и выдаче доступа в течение 1 рабочего дня.
2. Откройте ссылку под ответом. Сверьте название, раздел, строки и подсвеченный исходный текст. Помощник не проверяет, действует ли регламент в реальной организации.
3. Задайте «Какой бюджет на отпуск?». Подтверждённого ответа в базе нет. Нажмите «Подготовить обращение человеку», измените текст, проверьте контекст и скачайте JSON либо сохраните в очередь. Никто не получит уведомление.
4. Для проверки собственной загрузки добавьте `data/example-instructions.md`. Спросите «Как получить доступ в лабораторию?» — ответ содержит только учебные правила из этого файла. После замены/удаления документа задайте вопрос заново: прежний результат сбрасывается.
5. Дополнительные вопросы, конфликтующие документы и проверки безопасности перечислены в [CHECK-QUESTIONS.md](docs/CHECK-QUESTIONS.md).

## Где находятся данные

| Режим | Документы и вопросы | Обращения |
|---|---|---|
| Публичная статическая версия / статический локальный просмотр | Обрабатываются в браузере. По умолчанию живут в памяти вкладки; после обновления собственные изменения исчезают и снова загружается учебная база. | По умолчанию только в памяти вкладки. Перед закрытием можно скачать JSON. |
| Включено «Сохранять данные в этом браузере» | Документы сохраняются без шифрования в `localStorage`. | В браузерном режиме очередь также сохраняется без шифрования в `localStorage`. |
| `npm start` | Вопрос и текущие документы передаются локальному процессу на этом компьютере для поиска; сервер не сохраняет сами документы. При включённом браузерном сохранении документы дополнительно остаются в браузере. | После явного сохранения вопрос, контакт, контекст и выбранные цитаты записываются открытым текстом в `.local-data/tickets.json`. |

Ключ браузерного хранения включает путь проекта, чтобы разные демонстрации не перезаписывали данные случайно. Это разделение имён, а не защита от другого кода на том же origin. Не используйте демо для секретов, реальных контактов или чувствительных документов. Для одного набора данных используйте одну вкладку: синхронизация изменений между вкладками не реализована.

«Очистить базу» удаляет документы, но обращения содержат отдельные снимки цитат. В браузерном режиме удалите нужные обращения, очистите очередь или нажмите «Удалить сохранённое»: последняя кнопка очищает документы и браузерную очередь данного проекта, выключая сохранение. Она не удаляет файл серверной очереди и уже скачанные JSON. Отключение переключателя сохранения удаляет сохранённую браузерную копию, оставляя данные текущей вкладки до её обновления.

В статическом режиме содержимое инструкций и вопросов не отправляется приложением внешнему API. Сам хостинг получает обычные запросы за файлами сайта; это не обещание отсутствия технических журналов хостинга. В проекте нет аналитики, внешних шрифтов и средств рассылки.

## Как работает поиск и где его пределы

Поиск сравнивает значимые слова, некоторые русские окончания и небольшой словарь вариантов вроде «срм»/«CRM», «восстановить»/«сброс пароля». Он требует совпадения условий вопроса в одном разделе и возвращает исходный текст без сочинённых дополнений. Для двух явно разделённых тем поддержаны две выдержки. Максимум — две ссылки в ответе.

Это лексический алгоритм: он может не найти существующее правило при незнакомой формулировке, не проверяет истинность инструкции, не вычисляет даты и суммы и не устанавливает приоритет редакций. Различающиеся совпадающие фрагменты требуют уточнения: алгоритм не умеет надёжно отличить дополнение от противоречия. Противоречие внутри одного абзаца или скрытая смысловая неоднозначность могут остаться незамеченными. Совпадение слов не доказывает применимость правила; проверяйте исходник.

Разделы с явными попытками переопределить правила исключаются эвристическим фильтром. Фильтр не распознаёт любые возможные вредоносные формулировки. Фактическая граница программы — загруженный текст не исполняется как код или команда, не меняет программу и не передаётся модели. HTML и Markdown показываются как текст. Поле `confidence` в техническом ответе ядра не является вероятностью правильности.

Пределы интерфейса: 30 документов, до 100 000 символов в каждом и 500 000 суммарно; вопрос до 1200 символов; очередь до 500 обращений. Для поиска раздел должен быть не длиннее 12 000 символов — большие инструкции разделите заголовками Markdown. Повреждённый UTF-8, бинарные/управляющие символы, пустой текст и неподдерживаемые расширения отклоняются. PDF и Word нужно предварительно сохранить как обычный UTF-8 текст; OCR и разбор этих форматов не подключены.

## Структура

| Путь | Назначение |
|---|---|
| `index.html`, `styles.css`, `favicon.svg` | Интерфейс, адаптивная вёрстка, оформление |
| `src/app.js` | Загрузка, источники, браузерное хранение, форма и очередь |
| `src/engine.js` | Общий детерминированный поиск для браузера и сервера |
| `data/demo-documents.json` | Четыре вымышленные инструкции |
| `data/example-instructions.md`, `data/checks/` | Загружаемый пример, конфликт, замена и недоверенный текст |
| `server/server.js` | Отдельный локальный HTTP-сервер и файловая очередь |
| `tests/` | Тесты движка и серверного контракта |
| `scripts/build.js` | Сборка статического `dist/` без приватных данных |
| `docs/` | Локальный сервер, контрольные вопросы, кейс |

## Публикация

Цель публикации — отдельный бесплатный GitHub Pages проект `istochnik-knowledge-demo` с `build_type=workflow` и официальными Actions `configure-pages`, `upload-pages-artifact`, `deploy-pages`. Артефакт — только `dist/`; относительные пути `./` поддерживают базовый путь `/istochnik-knowledge-demo/`. Сервер, тесты, приватное хранилище и внутренние материалы в статический артефакт не копируются.

Текущий статус публикации указан в начале README. Публичный сценарий, версия исходников и успешный workflow должны быть подтверждены отдельно; наличие исходников или сборки этого не доказывает. GitHub Pages не исполняет Node-сервер и не даёт общей очереди между устройствами.

Визуальные материалы и шрифты описаны в [ASSETS.md](ASSETS.md). Описание задачи и реализованного пути — в [CASE.md](docs/CASE.md).
