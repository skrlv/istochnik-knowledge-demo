# Локальный сервер и очередь сотрудника

Сервер — отдельный проверяемый вариант запуска. Он использует Node.js 22+ и встроенные модули, без внешних библиотек, API-ключей, платных сервисов и исходящих уведомлений.

В корне проекта:

```sh
node server/server.js
```

Откройте <http://127.0.0.1:4316/>. Сервер слушает только `127.0.0.1`. Другой порт можно задать перед запуском:

```sh
PORT=4317 node server/server.js
```

Очередь сохраняется в `.local-data/tickets.json`, переживает перезапуск и отделена от статической раздачи. Документы для поиска отправляются только этому локальному процессу и сами по себе не сохраняются сервером. После явного сохранения обращения на диске остаются вопрос, контакт, ответ и выбранные цитаты источников. Для отдельной папки хранения:

```sh
DATA_DIR=./local-demo-queue node server/server.js
```

Не добавляйте папку данных в репозиторий. Там может оказаться введённый контакт. Сервер задаёт папке очереди права `0700`, а файлу — `0600` (только владелец); это относится и к выбранному `DATA_DIR`, поэтому используйте отдельную папку. Папка очереди не может совпадать с корнем сайта. На одном хранилище запускайте один процесс сервера: блокировки между несколькими процессами нет.

Чтобы удалить локально сохранённые вопросы, остановите сервер и удалите `.local-data/tickets.json` (либо этот файл в собственном `DATA_DIR`). При следующем запуске очередь будет пустой. Удаление файла не стирает уже скачанные экспорты или резервные копии. Не загружайте в публичную демонстрацию реальные секреты и медицинские/чувствительные данные.

## Что действительно работает

- `POST /api/answer` выполняет поиск по переданным инструкциям общим ядром; документов и ответов платный API не получает.
- `POST /api/tickets` записывает вопрос и снимок источников в файл на этом компьютере.
- `GET /api/tickets` читает сохранённую очередь; `PATCH /api/tickets/:id` меняет статус сотрудником.
- Локальная постановка в очередь не означает отправку человеку в почту, Telegram или CRM. Подключённого внешнего получателя нет.

На GitHub Pages сервер не выполняется. Публичная версия хранит демонстрационную очередь в браузере и явно показывает этот режим. Переход к локальному серверу — отдельный запуск, а не скрытая интеграция.

Сервер возвращает данные как JSON; клиент обязан выводить их через безопасный текстовый вывод, не через HTML. Передаваемые в обращении источники — снимок, подтверждённый пользователем при просмотре, а не серверная цифровая подпись или независимая проверка происхождения документа.

Пустой список `sources: []` допустим. Каждый переданный источник должен содержать непустые строки `documentId`, `documentTitle`, `sectionId`, `heading`, `quote`, а также положительные целые `startLine` и `endLine` с концом не раньше начала. Неполные снимки отклоняются и при HTTP-записи, и при чтении сохранённого файла. Пробелы и переносы внутри цитаты сохраняются точно.

## Проверка вручную

Проверить режим:

```sh
curl http://127.0.0.1:4316/api/health
```

Ожидается `{"ok":true,"mode":"local-server"}`.

Создать вопрос:

```sh
curl http://127.0.0.1:4316/api/tickets \
  -H 'Content-Type: application/json' \
  --data '{"question":"Кто согласует нестандартный запрос?","answer":"В инструкциях нет ответа.","sources":[]}'
```

Ответ `201` содержит `ticket.id`. Посмотреть очередь:

```sh
curl http://127.0.0.1:4316/api/tickets
```

Для смены статуса подставьте полученный ID:

```sh
curl -X PATCH http://127.0.0.1:4316/api/tickets/TICKET_ID \
  -H 'Content-Type: application/json' \
  --data '{"status":"in_progress"}'
```

Допустимые статусы: `new`, `in_progress`, `closed`.

Обратиться к поисковому ядру с собственным документом:

```sh
curl http://127.0.0.1:4316/api/answer \
  -H 'Content-Type: application/json' \
  --data '{"question":"Как часто меняют пароль для тестового стенда?","documents":[{"id":"test","title":"Тестовая инструкция","filename":"test.md","text":"# Доступ к стенду\nПароль для тестового стенда меняют каждые 30 дней."}]}'
```

## Ограничения и защита демонстрации

Запросы разрешены только с этого компьютера, с корректным локальным `Host`. Чужой `Origin`, `null` и межсайтовые браузерные запросы отклоняются; CORS-доступ не включён. Данные передаются как JSON в UTF-8 и не исполняются как инструкции к серверу. Статика ограничена `index.html`, `styles.css`, `favicon.svg` и папками `src/`, `data/`, `assets/`; разрешённость проверяется и после раскрытия символьных ссылок. Скрытые файлы, хранилище, код сервера, тесты и ссылки на закрытые либо внешние пути не раздаются. Запись очереди последовательная и атомарная в пределах одного процесса. Повреждённый файл данных, неверные поля или повторяющиеся ID приводят к отказу запуска, а не к перезаписи очереди.

Пределы сервера:

| Что | Предел |
| --- | --- |
| Тело HTTP-запроса | 1 500 000 байт |
| Документы в запросе поиска | 30 файлов, до 100 000 символов каждый, до 500 000 суммарно |
| Вопрос в обращении / запросе | 2 000 символов; ядро просит сократить поисковый вопрос длиннее 1 200 |
| Ответ / контакт в обращении | 30 000 / 250 символов |
| Источники в обращении | 10, до 15 000 символов на цитату |
| Сохранённая очередь | 500 обращений |

Недопустимые поля и неподдерживаемое содержимое документов дают `400`, неверный тип запроса — `415`, слишком большой HTTP-запрос — `413`, переполненная очередь — `409`. Если цитата слишком длинная для сохранения, сократите подготовленный пользователем текст или экспортируйте его из браузера; сервер не обрезает сведения молча.

Это однопользовательская локальная демонстрация. Проверка `Origin` не заменяет вход сотрудников и не защищает от другого вредоносного приложения на том же компьютере. Вопросы и контакты хранятся открытым текстом. Для реального общего кабинета понадобятся подтверждённые инструкции, серверное размещение, HTTPS, вход и права сотрудника, журнал действий, политика хранения/удаления данных, резервные копии и выбранный пользователем канал уведомлений. Эти подключения не выполнены и не нужны для демонстрации.

## Автоматическая проверка

```sh
node --test tests/server.test.js
```

Тесты используют временное хранилище и случайный локальный порт. Они проверяют реальную запись и перезапуск, параллельное сохранение в одном процессе, изменение статусов, права файлов, отказ чужому сайту, ограничения ввода, строгий JSON/UTF-8, закрытые файлы, обход путей, символьные ссылки и вызов общего ядра. Реальные сообщения и внешние API не используются.
