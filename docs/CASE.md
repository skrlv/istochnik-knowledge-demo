# ИСТОЧНИК — помощник по инструкциям

Демонстрационный продукт для ситуации, когда сотруднику нужен ответ по внутреннему регламенту и возможность проверить, откуда он взят. Компания «Линия» и все документы вымышлены. Это самостоятельный концептуальный проект, а не описание внедрения у клиента.

## Задача

Собрать понятный путь от загрузки инструкции к найденному фрагменту и дальнейшему вопросу человеку. Пользователь должен видеть границу базы: отсутствие сведений не подменяется придуманным советом, а различающиеся источники не превращаются в автоматически выбранное правило.

## Реализованный путь

Слева находится библиотека документов с добавлением, просмотром, заменой и удалением. Справа — вопрос, несколько учебных примеров и ответ. Найденный ответ состоит из буквального текста; ссылка открывает исходный документ, номера строк и подсветку использованного раздела. Изменение базы сбрасывает прежний результат, чтобы он не выглядел актуальным.

Если источника недостаточно, интерфейс позволяет подготовить обращение. Перед сохранением пользователь меняет вопрос и контекст, проверяет цитаты и решает, прикладывать ли их. Затем можно скачать JSON или сохранить запись в локальную очередь и менять её статус. Реального оператора и внешней доставки нет.

## Два режима

Статическая демонстрация предназначена для бесплатного GitHub Pages: поиск выполняется в браузере, данные по умолчанию существуют в памяти вкладки. Сохранение документов и очереди в браузере включается отдельно и происходит без шифрования.

Локальный Node-сервер использует то же поисковое ядро, принимает инструкции на этом компьютере и сохраняет обращения в отдельный файл с ограниченными правами. Этот режим проверяется отдельно и не объявляется возможностью GitHub Pages. Для совместной рабочей системы потребуются серверное размещение, вход сотрудников, права, политика хранения и выбранный канал уведомлений.

## Решения

- Дословная выдержка и открываемый исходник позволяют сравнить ответ с текстом правила.
- Контрольные документы воспроизводят конфликт сроков, замену редакции и попытку инструкцией изменить поведение помощника.
- Сохранение в браузере выключено по умолчанию; место хранения и отдельные копии цитат в обращениях объяснены в интерфейсе.
- Платный API отсутствует. Ограниченный поиск по словам делает запуск воспроизводимым, но требует честно показывать пределы перефразирования и смыслового анализа.
- Визуальное оформление использует спокойный фон, зелёный акцент для источников и контрастный цвет уточнения; отдельные области помогают различить библиотеку, вопрос и обращение. Системные шрифты и геометрия CSS/SVG не требуют внешней загрузки.

## Проверяемый результат

Исходники, тесты, пример базы, контрольные вопросы, локальный сервер и воспроизводимые команды находятся в одном проекте. Проверки движка и серверного контракта запускаются через `npm test`; полный локальный набор — `npm run check`. Пользовательские сценарии описаны в [CHECK-QUESTIONS.md](CHECK-QUESTIONS.md), сервер — в [LOCAL-SERVER.md](LOCAL-SERVER.md).

На момент подготовки этого описания итоговая проверка интерфейса и публичной публикации ещё ожидает подтверждения владельцем задачи. Актуальный статус и ссылка должны браться из [README](../README.md), а не выводиться из наличия данного кейса.

## Ограничения

Проект не измеряет экономию времени, качество поддержки или коммерческую эффективность. Данных о клиентах, пользователях и внедрении нет. Алгоритм не является нейросетевой моделью, не доказывает истинность загруженных правил и может ошибиться в применимости найденного текста. Явные попытки сменить правила фильтруются эвристически; загруженный текст вообще не исполняется. Содержимое документов, очереди и экспортов нельзя считать защищённым хранилищем секретов.
